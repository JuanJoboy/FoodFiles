# Build & Environment Recovery Documentation (Flutter 3.50 / AGP 9)

## 1. Root Cause Summary

Upgrading the project toolchain to **Flutter 3.50.0 (previously 3.38.5)**, **Dart 3.14.0 (previously 3.10.4)**, **Android Gradle Plugin (AGP) 9.3.1 (previously 8.11.1)**, and **Gradle 9.9.1 (previously 8.14-all)** introduced four simultaneous breaking changes:

1. **AGP 9 Built-in Kotlin Conflict:** AGP 9 enables `android.builtInKotlin=true` by default and throws an error if any module applies the legacy `id("kotlin-android")` plugin. Conversely, setting `builtInKotlin` to false breaks modern plugins that dropped `kotlin-android` from their Gradle files.
2. **Java Bytecode Mismatch:** Gradle executed `javac` with an older JDK while build scripts targeted Java 21, causing `invalid source release: 21`.
3. **Transitive Dependency Locks:** Legacy packages (`currency_converter_pro`, `supabase_codegen`) pinned outdated `intl` and `win32` versions, blocking resolution of AGP-9-compatible plugins. Newer plugins required the newer version of `intl 0.20.2` but the outdated plugins needed `intl 0.18.1`.
4. **Android `aapt2` Asset Filtering & Emulator Storage:** Newer Gradle asset mergers silently strip root dotfiles (`.env`) during APK packaging, and larger native Mapbox binaries (100-150 MB) exceed default Android emulator disk partitions.

## 2. Failure Log & Resolution Matrix

| Error Message | Cause | Fix Applied |
| --- | --- | --- |
| `invalid source release: 21` | `javac` ran on JDK 17 while `build.gradle.kts` targeted Java 21. | Aligned `sourceCompatibility`, `targetCompatibility`, and `jvmTarget` to `JavaVersion.VERSION_17` / `JvmTarget.JVM_17`. |
| `Could not find method kotlin()` in `mapbox_maps_flutter_mobile` | `android.builtInKotlin=false` stripped Kotlin support from Mapbox 3.35.0, which already removed `apply plugin: 'kotlin-android'`. | Injected `apply(plugin = "kotlin-android")` dynamically via a `beforeEvaluate` hook in root `android/build.gradle.kts`. |
| `Failed to apply plugin 'org.jetbrains.kotlin.android'` in `package_info_plus` | Enabling `android.builtInKotlin=true` broke `package_info_plus` (pulled in by `geolocator`), which still applies `kotlin-android`. | Kept `android.builtInKotlin=false` and `android.newDsl=false` in `gradle.properties` to satisfy both plugins. |
| `version solving failed` (`intl` & `win32` conflicts) | `currency_converter_pro` locked `intl ^0.18.0`; `supabase_codegen` locked `win32 ^5.0.0`. | Replaced `currency_converter_pro` with `currency_converter: ^3.0.0` and removed unused `supabase_codegen`. |
| `resource string/mapbox_access_token not found` | `mapbox_access_token.xml` is gitignored and missing on secondary machines. | Recreated `android/app/src/main/res/values/mapbox_access_token.xml` locally on each machine. |
| `INSTALL_FAILED_INSUFFICIENT_STORAGE` | Debug APK size with Mapbox native libraries exceeded the emulator's default disk partition. | Set `disk.dataPartition.size=8G` in the AVD `config.ini` and cold-booted with `-wipe-data`. |
| `FileNotFoundError: Environment file ".env" not found` | AGP 9 `aapt2` ignored the root `.env` dotfile when bundling `flutter_assets`. | Renamed `.env` to `assets/env`, updated `pubspec.yaml` and `dotenv.load()`, and gitignored `assets/env`. |

## 3. What Worked (Final Working Configuration)

### Gradle Properties (`android/gradle.properties`)

Retains legacy Kotlin and DSL flags until all transitive dependencies migrate to AGP 9 built-in Kotlin:

```properties
org.gradle.jvmargs=-Xmx8G -XX:MaxMetaspaceSize=4G -XX:ReservedCodeCacheSize=512m -XX:+HeapDumpOnOutOfMemoryError
android.useAndroidX=true
android.enableJetifier=true
org.gradle.caching=true
org.gradle.parallel=true
android.builtInKotlin=false
android.newDsl=false

```

### Root Gradle Hook (`android/build.gradle.kts`)

Patches `mapbox_maps_flutter_mobile` at evaluation time so the fix stays tracked in Git across all machines. Since this package is modern and does utilise the `builtInKotlin` flag that AGP 9 provides, but other packages don't utilise it, the `build.gradle.kts` file has the following section added so that the `kotlin-android` plugin is manually added. As `gradle.properties` sets `builtInKotlin=false`:

```kotlin
subprojects {
    if (name == "mapbox_maps_flutter_mobile") {
        beforeEvaluate {
            apply(plugin = "kotlin-android")
        }
    }
}

subprojects {
    project.evaluationDependsOn(":app")
}

```

### App Gradle Config (`android/app/build.gradle.kts`)

Aligns SDK 37 (required by `permission_handler_android`) with Java 17 compilation targets. It used to say `compileSdk = flutter.compileSdkVersion`, which allows `flutter upgrade` to automatically upgrade the project. Hardcoding 37 is not objectively better - it is a mandatory override to resolve a dependency mismatch.

The AAR Metadata Rule: Android Gradle Plugin (AGP) forbids building an app with an older compileSdk than the libraries it imports. permission_handler_android (and its underlying AndroidX dependencies) compiled against Android API 37, whereas Flutter 3.50's flutter.compileSdkVersion still defaulted to an older API level (35 or 36).

The downside of hardcoding 37 is that the app will stay pinned to 37 even after Flutter moves past it. Once a future Flutter release bumps its internal default to 37 or higher, switch it back to compileSdk = flutter.compileSdkVersion to resume automatic updates.

```kotlin
android {
    namespace = "com.example.food_files_app"
    compileSdk = 37
    ndkVersion = flutter.ndkVersion

    compileOptions {
        sourceCompatibility = JavaVersion.VERSION_17
        targetCompatibility = JavaVersion.VERSION_17
    }
    ...
}

kotlin {
    compilerOptions {
        jvmTarget.set(JvmTarget.JVM_17)
    }
}

```

### Environment Variables (`pubspec.yaml` & `lib/main.dart`)

Uses a standard non-dotfile asset path so `aapt2` always packages the file.

The `.env` file broke because of a conflict between how **Flutter's asset compiler** registers files and how **Android's AAPT2 (Android Asset Packaging Tool 2)** packages them into the APK under AGP 9.

##### The Exact Chain of Events

1. **Flutter Registered the File (`AssetManifest.bin`):**
When `flutter run` is ran, Flutter's build tool reads `pubspec.yaml`, ses `- .env`, and writes `.env` into the app's internal asset index (`AssetManifest.bin`).
2. **Android Stripped the File (`aapt2`):**
On Unix/Linux/macOS systems (and Android's build tools), any filename starting with a dot (`.`) is treated as a hidden system/metadata file (like `.git` or `.DS_Store`). Android's asset merger uses a default exclusion filter (`ignoreAssetsPattern`) containing the wildcard `.*` to stop hidden metadata from bloating APKs.
3. **Runtime Crash (`FileNotFoundError`):**
At runtime, `dotenv.load()` checked `AssetManifest.bin`, saw that `.env` was supposed to exist, and asked Android's `AssetManager` to open it. Because `aapt2` had silently dropped the file during APK packaging, Android returned nothing, and `flutter_dotenv` threw `FileNotFoundError`.

##### Why It Worked in July vs. November

* **Older AGP / Flutter Gradle Plugin (July):** Legacy Flutter Gradle scripts copied `flutter_assets` into the APK using custom packaging tasks that bypassed or overrode AAPT2's default `.*` dotfile filter.
* **AGP 9 / Flutter 3.50 (November):** The updated Flutter Gradle plugin delegates asset merging directly to AGP 9's standard Android resource/asset pipeline, enforcing AAPT2's strict `.*` exclusion rule by default.

##### Why `assets/env` Fixed It

* **Removing the dot (`env`):** Without the leading `.`, the file no longer matches AAPT2's `.*` ignore rule, so Android packages it into the APK normally.
* **Moving to `assets/`:** Keeping non-hidden configuration files inside `assets/` prevents root directory clutter while matching Flutter's standard asset resolution path.

* **File location:** `assets/env` (listed in `.gitignore`)
* **`pubspec.yaml`:**
```yaml
assets:
  - assets/images/
  - assets/env

```


* **`lib/main.dart`:**
```dart
await dotenv.load(fileName: "assets/env");

```

## 4. What to Avoid (And Why)

* **Never edit files inside `AppData\Local\Pub\Cache`:** Manual edits to cached plugins are untracked by Git, wiped by `flutter pub cache repair`, and fail silently when cloning onto another PC. Always inject Gradle fixes through `android/build.gradle.kts`.
* **Never put CLI/codegen tools in `dependencies:`:** Packages like `supabase_codegen` pull in desktop libraries (`dcli`, `win32`) that conflict with mobile plugin dependencies. Use standalone CLIs (`supabase gen types dart`) or manual Dart `fromJson`/`toJson` models instead.
* **Never name Flutter asset files with a leading dot (`.env`):** Android's `aapt2` asset merger treats dotfiles as hidden/ignored files in newer AGP releases, causing runtime `FileNotFoundError` crashes despite being declared in `pubspec.yaml`.
* **Avoid `dependency_overrides` unless strictly necessary:** Forcing incompatible versions masks transitive API mismatches and breaks builds when upgrading unrelated packages.
* **Do not run blind major upgrades without checking native Android plugins:** Always inspect `flutter pub outdated` and check changelogs for `mapbox_maps_flutter`, `geolocator`, and `permission_handler` before bumping AGP or Flutter major versions.

## 5. Troubleshooting Playbook

### Fixing Emulator `INSTALL_FAILED_INSUFFICIENT_STORAGE` (Without Android Studio)

1. Kill the running emulator:
```cmd
"%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe" emu kill

```


2. Open `%USERPROFILE%\.android\avd\<AVD_NAME>.avd\config.ini` and set:
```ini
disk.dataPartition.size=8G

```


3. Cold-boot and wipe the virtual disk once:
```cmd
"%LOCALAPPDATA%\Android\Sdk\emulator\emulator.exe" -avd <AVD_NAME> -wipe-data

```



### When Can the Gradle Workarounds Be Removed?

Once `geolocator` updates `geolocator_linux` to depend on a version of `package_info_plus` that removes `apply plugin: 'kotlin-android'`:

1. Delete `android.builtInKotlin=false` and `android.newDsl=false` from `android/gradle.properties`.
2. Delete the `if (name == "mapbox_maps_flutter_mobile")` block from `android/build.gradle.kts`.
3. Run `flutter clean && flutter pub get`.
